# Расширение Videoner для браузера

Скачивает видео со страницы, где его смотрят: кнопка «Скачать» в углу
страницы видео (или клик по значку Videoner в панели браузера) → выбор
качества → файл в «Загрузках». Работает в Chrome, Яндекс Браузере, Edge,
Opera и Firefox (с 1.4.0 — см. «Firefox» ниже).

Кнопка появляется только на странице конкретного видео или поста, не на
главной и не в ленте. Крестик на ней прячет её до перехода к другому видео.

TikTok, Threads, Instagram и Facebook браузер скачивает сам, если на странице
есть готовый mp4 (`page-media.js`), — без очереди на сервере и со входом
человека на площадке: закрытое видео, которое он видит под своим аккаунтом,
тоже скачается, а куки не покидают браузер. Сервер получает только отчёт для
статистики (`POST /api/ext/download/report`). Не вышло — тот же ролик
автоматически качается через сервер. Остальные площадки, а также другие
качества и звук, скачивает сервер Videoner, как для сайта и бота. Расширение ходит в API через
`https://videoner.download/api/ext/*` (без капчи, с лимитами по IP — см.
`web/app/api/ext/[...path]/route.ts`), а за ходом скачивания следит по
публичному `/download/<id>/status`. Скачивания из расширения видны на
дашборде с источником «Расширение».

## Уроки GetCourse

Школа живёт на своём домене, а видео урока — в плеере GetCourse внутри
страницы (iframe `…/sign-player/` на доменах GetCourse, одних для всех школ).
Скрипт `getcourse.js` работает только в этом плеере: берёт из его настроек
адрес HLS-потока, ставит в углу плеера кнопку «Скачать» и сообщает о плеере
фоновой части — окошко по значку покажет все видео урока. Доступа ко всем
сайтам расширению для этого не нужно.

Качает и склеивает урок браузер (`gc-remux.js`): в Chrome — на скрытой
странице расширения (`gc-offscreen.html`, `gc-offscreen.js`), в Firefox —
прямо в фоновой части. Кусочки .ts идут по шесть параллельно и
перекладываются в mp4 библиотекой mux.js
(`vendor/mux.min.js`, 7.1.0, Apache-2.0) без перекодирования. Файл копится в
памяти и сохраняется целиком (40 минут в 1080p — около гигабайта). Запросы
идут из браузера ученика, так что всё, что он видит под своим входом в
школу, скачается; сервер получает только отчёт для статистики — адрес потока
без подписи и данных ученика. Не вышло в браузере (шифрованный поток, сбой
сети) — тот же поток в том же качестве качает сервер (yt-dlp). Подпись
потока сервер открывает с чужого IP, но проверено это только на открытом
уроке.

Название файла — заголовок вкладки, если окошко открыто значком; из кнопки на
плеере заголовок страницы школы недоступен (другой домен), и файл называется
«Урок GetCourse».

## Firefox

Та же папка `extension/`, отличается только сборка (`scripts/pack-extension.sh`
→ `dist/firefox/`): свой manifest (фоновая часть — страница `background.html`
вместо service worker, без `offscreen`, идентификатор
`videoner@videoner.download`, обновления с нашего сайта) и без
`gc-offscreen.*`. Отличия Firefox, которые учтены в коде (проверено
29.10.2026 в Firefox 153):

- окошку в рамке на чужой странице (кнопка «Скачать») Firefox даёт только
  `runtime`, `i18n` и `storage` без `session` — нет `tabs` и `downloads`. Тогда
  окошко спрашивает о вкладке и хранилище фоновую часть (`popup.js`
  `activeTab`/`sendToTab`, `shared.js` `session`, `background.js`
  «embed-tab», «embed-storage»);
- нет `storage.session.onChanged` — везде общее `storage.onChanged`;
- фоновую страницу Firefox усыпляет примерно через 30 секунд без событий, а
  сетевые запросы событием не считаются — урок в 1080p обрывался. Пока урок
  склеивается, фоновая часть раз в 4 секунды пишет метку в `storage.session`
  и сама получает событие `storage.onChanged` (`background.js`, `keepAlive`);
- в API сайта расширение приходит с `Origin: moz-extension://…` (у каждой
  установки свой адрес) — его пускает `web/app/api/ext/[...path]/route.ts`.

Проверка: `web-ext lint -s dist/firefox --self-hosted`; поставить для пробы —
`about:debugging` → «Этот Firefox» → «Загрузить временное дополнение» →
`dist/firefox/manifest.json`. Обычный Firefox ставит только подписанное
Mozilla дополнение: подписываем без публикации в каталоге (unlisted), файл
`.xpi` кладём в `web/public/extension/videoner-firefox.xpi`, его версию — в
`web/lib/extension-firefox-version.ts`, а для обновлений —
`web/public/extension/firefox-updates.json` (адрес — в `update_url` сборки;
формат — список версий со ссылками на свои .xpi). Сайт отдаёт .xpi с типом
`application/x-xpinstall` — без него Firefox сохранил бы файл, а не предложил
установку; .xpi и .json не проходят через языковой middleware сайта
(`web/middleware.ts`). Пока там `null`, страница
videoner.download/extension пишет Firefox-пользователям «скоро».

Подпись новой версии (поднять `version` в manifest, затем):

1. `./scripts/pack-extension.sh`.
2. Ключи Mozilla (AMO, аккаунт владельца) лежат в Infisical, проект videoner,
   окружение Development: `AMO_JWT_ISSUER`, `AMO_JWT_SECRET`. Выгрузить их в
   файл `~/.config/videoner-amo.env` (права 600) — не в `.env` проекта.
3. ```
   docker run --rm -u $(id -u):$(id -g) -e HOME=/tmp --env-file ~/.config/videoner-amo.env \
     -v $PWD/dist:/d node:22-bookworm-slim sh -c 'npx -y web-ext@8.3.0 sign \
     --channel unlisted --source-dir /d/firefox --artifacts-dir /d/signed \
     --api-key "$AMO_JWT_ISSUER" --api-secret "$AMO_JWT_SECRET"'
   ```
   Mozilla проверяет и подписывает автоматически, обычно за пару минут.
4. Скопировать `dist/signed/*-<версия>.xpi` в
   `web/public/extension/videoner-firefox.xpi`, вписать версию в
   `web/lib/extension-firefox-version.ts`, а в `firefox-updates.json` — новую
   версию, `update_link` с `?v=<версия>` и `update_hash` (sha256 файла).
   Задеплоить web: установленные расширения обновятся сами в течение суток.

## Установка вручную

В магазин расширений Videoner не выкладывается — ставится из архива.

1. Распакуйте архив `videoner-extension-<версия>.zip` в постоянное место
   (не во временную папку: браузер читает расширение оттуда при каждом
   запуске). Получится папка `videoner-extension`.
2. Откройте страницу расширений: `chrome://extensions` в Chrome,
   `browser://extensions` в Яндекс Браузере, `edge://extensions` в Edge.
3. Включите «Режим разработчика» (переключатель вверху справа или слева
   внизу — зависит от браузера).
4. Нажмите «Загрузить распакованное расширение» и выберите папку
   `videoner-extension`.
5. Браузер предупредит, что расширению нужен доступ к страницам YouTube,
   TikTok, Instagram и других площадок — без него не показать кнопку
   «Скачать» на странице видео.
6. Закрепите значок Videoner на панели (значок пазла → булавка).

Chrome может при запуске предлагать отключить расширения в режиме
разработчика — это предупреждение для всех расширений не из магазина,
Videoner работает дальше.

### Обновление

Распакуйте новый архив поверх той же папки и нажмите «Обновить» (стрелка по
кругу) на карточке Videoner на странице расширений.

### Сборка архива

`scripts/pack-extension.sh` → `dist/videoner-extension-<версия>.zip`. Версию
перед раздачей поднимите в `manifest.json`. Скрипт заодно кладёт архив на
страницу сайта videoner.download/extension (`web/public/extension/`,
`web/lib/extension-version.ts`) — закоммитьте их и задеплойте web.

Туда же ведут бот и сайт, когда площадка не отдала ролик серверу, а
расширение скачает его под входом человека (`bot/src/helpers.ts`
`extensionLinkFor`, `web/lib/extension-hint.ts`).

## Устройство

- `popup.html`, `popup.js`, `popup.css` — окошко: качества, прогресс, ошибки.
- `background.js` — запускает скачивание, следит за ним и сохраняет файл в
  «Загрузки»; работает, даже когда окошко закрыто.
- `shared.js` — адрес API, тексты на русском и английском, перевод ошибок.
- `content.js`, `video-pages.js` — кнопка на страницах площадок; по клику
  открывает то же окошко в рамке (`popup.html?embed=1&url=…`).
- `getcourse.js`, `getcourse-hls.js`, `gc-remux.js`, `gc-offscreen.*`,
  `vendor/` — уроки GetCourse (см. выше).
- `background.html` — фоновая часть в Firefox (подключает mux.js и
  `background.js`); Chrome её не использует.
