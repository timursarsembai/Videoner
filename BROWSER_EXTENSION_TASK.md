# Задача: расширение для браузера

Поставлена владельцем 26.09.2026. Первая версия (все площадки, кроме GetCourse)
сделана 27.10.2026 — код в `extension/`, устройство и установка в
`extension/README.md`. Ниже — что решено, что осталось и разбор GetCourse.
Прочитай целиком, прежде чем браться за продолжение.

## Состояние на 27.10.2026

Сделано (версия 1.0.0):

- Окошко по клику на значок: качества с размерами, звук, субтитры YouTube,
  прогресс, сохранение в «Загрузки» через `chrome.downloads`. Скачивание ведёт
  фоновая часть (`background.js`), окошко можно закрыть.
- Кнопка «Скачать» на странице видео — плавающая, в углу (не вставка у
  плеера: под 11 вёрсток она ломалась бы). Открывает то же окошко в рамке.
- Вход в API для расширения `web/app/api/ext/[...path]` — общий код с прокси
  сайта в `web/lib/api-proxy.ts`. Ход скачивания расширение опрашивает по
  публичному `/download/<id>/status`, не через этот вход (см. ниже).
- Источник скачивания `EXTENSION` в базе: отдельно виден на дашборде, на него
  действует суточный лимит трафика YouTube по IP (вместе с сайтом).
- Раздача — только вручную: `scripts/pack-extension.sh` →
  `dist/videoner-extension-<версия>.zip`. В магазин не выкладываем.

Проверено в headless Chromium (Playwright, образ на сервере): окошко,
скачивание из кеша и свежее, тёмная тема, кнопка на странице (заглушка
YouTube с Trusted Types CSP), смена видео без перезагрузки страницы, установка
из архива.

Не проверено — нужен живой браузер владельца: итоговое имя файла в
«Загрузках» (Playwright подменяет имена), кнопка на настоящих сайтах площадок
(не перекрывает ли их элементы), Яндекс Браузер и Edge.

Осталось:

1. **Скачивание силами браузера** для площадок, где на странице уже есть
   готовый mp4 одним файлом (TikTok, Instagram, X, Pinterest, Threads, частично
   VK): расширение сохраняет его само, сервер не тратит трафик; не вышло —
   переход на серверный путь. Статистика — коротким отчётом серверу после
   каждого скачивания (площадка, ссылка, размер, успех), в ту же таблицу
   `Download` с источником `EXTENSION` и пометкой «скачано в браузере». YouTube
   остаётся на сервере (шифр потоков, раздельные видео и звук). Решено с
   владельцем 27.10.2026.
2. **GetCourse** — разбор ниже.

## Решения (27.10.2026)

- **Капчи у расширения нет**, только лимиты по IP: 30 запросов в минуту на
  всё и 10 в минуту на `/info`. Вход узнаёт расширение по `Origin:
  chrome-extension://…` — это отсекает чужие сайты, но не скрипты вне
  браузера. Владелец выбрал это осознанно, вместо варианта «расширение
  открывает сайт с капчей».
- **Источник ставит прокси, а не клиент**: раньше через прокси сайта можно
  было прислать `source: "BOT"` и обойти лимит YouTube.
- **Статус — по публичному адресу**: GET из фоновой части Chrome отправляет
  без `Origin`, а опрос раз в 2 секунды съел бы весь лимит входа.
- **Настоящий IP посетителя**: сайт за Cloudflare, и NPM видел адреса узлов
  Cloudflare — все лимиты «по IP» были общими на всех за одним узлом.
  Исправлено в NPM (`real_ip_header CF-Connecting-IP;` в Advanced хоста
  videoner.download, сохранено и в его базе). Прямо к серверу в обход
  Cloudflare заголовок не подделать: NPM доверяет ему только с адресов
  Cloudflare.

## Что нужно

Расширение для Chrome (и совместимых: Яндекс Браузер, Edge), которое скачивает
видео через Videoner прямо со страницы, где человек его смотрит.

Площадки — **все, которые Videoner уже поддерживает**: YouTube, TikTok,
Instagram, Facebook, Twitter/X, Vimeo, VK, Rutube, OK.ru, Pinterest, Threads.
И **GetCourse** в придачу — ради него расширение и задумано: закрытые уроки
сервер скачать не может (почему — ниже).

## Как разделить работу

Площадки делятся на два вида, и устроены они по-разному.

**Всё, кроме GetCourse, — расширение только передаёт ссылку.** Скачивает сервер,
ровно как сейчас для сайта и бота: `/info` → выбор качества →
`/download/video|audio|subtitles` → `/download/:id/status` → файл по
`GET /download/:filename`. От расширения нужна кнопка «Скачать» на странице
видео (или окошко по клику на значок) и показ качеств, которые вернул `/info`.
Серверную часть переписывать не нужно.

**GetCourse — расширение само находит поток в браузере ученика.** Сервер тут
бессилен: урок виден только вошедшему ученику, а ссылки подписаны на его IP.

## GetCourse: как устроено (разобрано 26.09.2026)

Образец — github.com/ohlexlexa/DownMax (расширение + приложение для macOS,
автор тоже писал с Claude Code). Смотреть `chrome-extension/popup.js`
(`collectPlayers`, `inspectPlayer`, `inspectStream`) и `background.js` (раздел
GetCourse), пояснения — в их `CLAUDE.md`.

1. Плееры на странице урока — iframe `…/sign-player/?json=<base64>`. В json лежит
   `video_hash`.
2. Страница плеера открывается без входа и содержит `previewUrl` (превью) и адрес
   потока `…/api/playlist/master/<video_hash>/<подпись>?…`.
3. Поток — HLS (`#EXTM3U`) со списком качеств (`RESOLUTION=`). Обычно
   незашифрованный: дальше его качает yt-dlp как есть. Если в плейлисте
   `#EXT-X-KEY` с методом не NONE — поток зашифрован, честно так и сказать.
   Иногда вместо m3u8 приходит JSON со ссылкой на плейлист внутри.
4. Запасной путь: `chrome.webRequest` ловит запросы `/api/playlist/master/`,
   пока видео играет, — для страниц, где плеер вставлен иначе.

**Главное ограничение.** В json плеера зашиты `ip` того, кто открыл страницу,
`user_role` и `time`. Проверено с сервера Contabo на открытой странице
`https://formfactor.getcourse.ru/materials`: вся цепочка прошла без браузера, но в
json оказался IP нашего сервера. Значит, ссылка на поток, добытая в браузере
ученика, подписана на ЕГО IP, и сервер её, скорее всего, не откроет. Отсюда
ключевой вопрос архитектуры, который надо решить первым (см. ниже).

## Что решить до кода (исходная постановка)

Пункты 2–4 решены (см. «Решения» выше: вход без капчи с лимитами по IP; входа
через Telegram на сайте с 04.10.2026 нет, лимиты — по IP; раздача вручную).
Открыт пункт 1 — он про GetCourse.

1. **Кто качает поток GetCourse.** Варианты: (а) сам браузер — расширение
   собирает HLS-сегменты и склеивает (без ffmpeg это только .ts; нужен mux в
   mp4 на стороне браузера, например mux.js), (б) расширение отдаёт ссылку
   серверу — сначала ПРОВЕРИТЬ, открывает ли сервер поток, подписанный на
   чужой IP. От ответа зависит половина работы. Проверять на открытой странице
   выше: получить master-ссылку с другого IP и запросить её с Contabo.
2. **Как расширение ходит в API.** Сервер (NestJS) требует `X-API-Key` — его в
   расширение класть нельзя, его видно любому. Сайт ходит через прокси
   `web/app/api/[...path]/route.ts`: там вход через Telegram (cookie сессии)
   и Cloudflare Turnstile на `/info`. Turnstile в расширении не пройти. Нужен
   свой путь: например, отдельный адрес для расширения с проверкой сессии
   Telegram без Turnstile, но со своим ограничением частоты. Решить с
   владельцем.
3. **Лимиты.** На сайте — вход через Telegram и 20 скачиваний в сутки
   (`enforceWebLimits`). Расширение, скорее всего, должно жить по тем же
   правилам и под тем же `telegramId`.
4. **Публикация.** Chrome Web Store (разовый взнос разработчика, проверка) или
   установка вручную из архива. Для GetCourse магазин может не пропустить —
   см. следующий пункт.

## Юридически

GetCourse — в основном платные курсы. Публичный сервис, который их выкачивает,
помогает нарушать права школ; это не то же самое, что YouTube. Владельцу это
сказано 26.09.2026, решение за ним. Сказать один раз, не повторять.
